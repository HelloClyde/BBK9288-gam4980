## 不得误报的状态

### ROM cache 物理页直接索引（2026-09-08）

- 为 `8.BIN` 和 `E.BIN` 各 512 个 4 KiB 物理页建立 `uint8_t` 缓存槽索引，合计 1024 字节外部 RAM，FF 表示未驻留。页编号只是 BIN 内物理偏移右移 12 位；6502 虚拟地址仍先通过当前 bank 解析，不是另造一层虚拟内存。
- `rom_cached_bank` 的命中路径，以及 `rom_read_byte` 的末次直接访问缓存未命中后的共享缓存查找，改为一次索引并核对该槽身份。缺页时才保留原 LRU/窗口锁定扫描；缓存容量仍为 64 槽，NAT 包和函数实现不变。
- 索引存放在 `.scratch`，每次 cache reset 显式初始化。预热整批成功后才发布；淘汰在读取前清除旧键，失败不发布新键。独立的单页 direct cache 策略不变，避免把该缓存的 FF 哨兵误当作共享缓存槽。
- `rom_cache_index_version=1`；新增 `rom_cache_index_bytes/lookups/hits/misses`，在 ROM 运行期统计重置点清零。已驻留整份 ROM 或最后一个 direct cache 的直接命中不查询索引，也不计入这些查询数。不要把该命中率当作所有 ROM 访存的命中率。
- 独立旧线性实现对照：32/64/128 槽共 49434 次检查，缓存数据、元数据、LRU、窗口归属、direct 别名、读取回调和 miss trace 一致；包含随机交错读写缓存状态、重置、预热成功和失败、边界页、不同 BIN 同页编号、过期索引及无效参数。普通构建与 AddressSanitizer 构建合计 98868 次检查通过。
- 独立模拟器片头至主菜单：43128 次索引查询，43092 命中、36 未命中；暂停检查完整索引和所有有效缓存槽的双向对应关系通过。NAT 全量索引仍只构建一次。这些是等价性和工作量验证，不能视为真机 FPS 提升。
- 继续进入开场剧情后：94749 次索引查询（93744 命中、1005 未命中），缓存元数据和完整索引再次双向核验通过；NAT 索引仍只构建一次。长按退出已恢复桌面；不是全剧情或系统菜单退出的完整回归。32/64/128 槽还分别通过非 PIE AddressSanitizer 检查。
- EXE 673849 字节，SHA256 `d9edd064093bdc7283920803bb930202a7c978c618a8788fdc1c9a84abbbdfaa`；IRAM 仍为 5392 字节，NAT SHA256 仍为 `d5491a1412cce7f5e09d91bb4a365e0521df843c5ce2f92bceb9e0d766bc3e7d`。

### FUNCTION NAT bank 路由优化（2026-09-08）

- 随后的真机复测：109 秒、2051 客机帧，18.816 fps / 31.36% 实时速度；95865 次 bank 刷新而索引构建仍为 1 次／129 项。NAT 成功执行 80431 次、54 个函数驻留、无驱逐，正常游戏退出且系统恢复成功。相对故障版的平均速度为 3.74 倍，相对此前未加载 NAT 的日志高约 15.8%；场景并非严格相同，不把它当作隔离的 NAT 净收益。最长按键扫描间隔降到 191 ms，但仍高于更早日志的 66 ms。
- 真机函数包首测：210 秒、1056 客机帧，约 5.028 fps / 8.38% 实时速度。核心路径计时 52930/53867 ticks，最长按键扫描间隔 148/256 秒。NAT 已执行 32373 次、加载 47 个函数、无驱逐；不是包未生效。与先前 16.243 fps 的场景并非严格相同，不能据此计算受控加速比。
- 发现额外成本：每次 bank 地址低／高字节写入都调用全量 NAT 路由重建。单次四窗口切换会执行八次清表及 129 个函数的扫描；清表合计 14 KiB。这是源码确定的新增工作，不代表已经独立测得它的宿主耗时。直接 ROM 读取的 344 ticks 不包括冷函数 malloc 暂停／恢复的全部耗时。
- FUNCTION 包改为打开时建立固定的候选入口页索引；运行调用同时检查精确虚拟入口和当前物理地址。bank 切换只更新 epoch，不再重建索引；相同映射不增加 epoch。按需加载、释放、失败和冷却也不再重建此索引。
- 只跳过 NAT 元数据的重复工作：同 bank 的 ROM cache 指针重绑定仍保留 `mem_bs`、内存页类型和取指指针更新。旧 NAT 和已绑定静态 GAM 原生代码继续保留其映射维护路径，不能直接照搬 FUNCTION 的跳过逻辑。
- 固件 HLE 入口另按物理 bank 建链，避免每次切换扫描整表；152 项 authored 表增加 434 字节外部 RAM 索引，不增加 IRAM。范围外的入口保留兜底桶及完整 bank/窗口检查。
- 回归：FUNCTION 2048 次随机切换逐一核对 129 个入口及内部地址，另验证错误 bank 不加载、原 bank 切回、缓存指针重绑定、冷却恢复、旧包和静态原生代码共存。HLE 索引四种编译组合共 625104 次位图／计数器对照通过；129 个函数专用化的 264192 组等价测试仍通过。
- 独立模拟器片头实测：4141 次 bank 刷新请求（913 次映射未变，3228 次实际切换），全量索引构建仍只有 1 次、描述符扫描合计 129 项。NAT 已调用 5897 次、加载 43 个函数。这是运行工作量和正确性验证，不是 9288 真机提速结论。
- 继续到新征程开场剧情：71501 次 bank 刷新（21761 次未变、49740 次实际切换），构建仍为 1 次／129 项；NAT 调用 60412 次、加载 45 个函数、无驱逐。片头、主菜单、开场剧情及长按退出回桌面通过；不等同于长时间全游戏或系统菜单退出路径的完整验证。测试使用隔离模拟器，未操作用户 Web 模拟器。
- 新日志 `native_bank_dispatch_version=2`，新增 `native_module_full_rebuilds/bank_refreshes/bank_nochanges/function_bank_fastpaths/rebuild_module_visits`，用于真机核对上述工作量。
- 目标 EXE 671265 字节，SHA256 `b894177c8372f230ac054b46bb49c04c169e02ab9ef234bd3b91f643fc66a2eb`；IRAM 5392 字节。配套 NAT 与上一函数包逐字节一致，不改变函数实现或包格式；仍需 8.BIN/E.BIN。

### 函数级 NAT 与按需内存（2026-09-08）

- 新包继续使用 GNAT format 4 / ABI 4，增加 FUNCTION `0x20`，与 FIRMWARE 合并为 `0x30`。每个函数只有一个可调用入口；其余 ROM match 记录仅用于检查该函数内联依赖，不能发布成入口。
- 构建时为每个明确入口常量折叠原处理器的入口选择，只保留该入口所需的 S1C33 代码。不得通过修改客机 PC 来选择函数；已接受操作的 PC 写回和 bank 恢复继续保持。
- 原生实现之间的必要辅助算法当前内联在各自函数中，目标对象必须零重定位；不需要把整个来源函数组一起加载。GAM 发起的动态客机调用仍由后续入口按需承接。
- 在现有 GAM CFG 恢复时收集已解析的固定 ROM 调用、C6502 far call 和直接 JMP 系统入口。不另扫完整游戏文件；不可达字节不当作调用。关闭加载时 AOT 时仍执行有界 CFG 分析。预载候选表有界，溢出或未知间接目标不会影响正确性，首次使用时仍可加载。
- FUNCTION 包使用独立 manifest 分配与逐函数代码分配；256 KiB 是代码工作集上限，不是启动时固定申请量。旧格式的连续 arena 只在确实加载旧包时兼容分配。代码缓存淘汰必须跳过正在执行、仍有宿主返回地址的函数。
- 当前函数包的静态清单：129 个入口，代码合计 87056 字节，manifest 55920 字节（含重复的依赖指纹）。文件变大不等于常驻代码变大；后续可单独压缩重复指纹，不把它混为执行代码。
- 根据本地三份 GAM 的 CFG 与函数包相交，预载代码预计为：伏魔记 31 个 / 18764 字节，魔塔 19 个 / 12364 字节，三国 51 个 / 32712 字节（代码四字节对齐）。这些只是启动预载计划，不是整段游玩的最大内存，也不是性能测量；后续首次调用会增加工作集。
- 完整 E.BIN 原生替代仍是另一项未完成的迁移任务；函数级打包、按需分配通过测试不代表 `resource_only_ready=true`。
- 最终目标构建：EXE 668089 字节，SHA256 `384b62ebaac5a585b8ed29fc762d005ac130f0fe233847d4e9abe47870510c66`；NAT 143850 字节，SHA256 `d5491a1412cce7f5e09d91bb4a365e0521df843c5ce2f92bceb9e0d766bc3e7d`。IRAM 仍为 5392 字节。
- 129 个专用化处理器共 264192 组与原处理器对照通过（184948 组接受执行），比较 CPU/RAM 及访存回调顺序；错误入口不得修改状态。另验证实际加载器的精确分配、重复调用、失败清理、活动代码保护、旧包兼容和预载 CFG。
- 最终独立模拟器 QMP 实测《伏魔记》：预载 31 个，片头按需增加后加载 43 个；manifest 55920 字节、代码 24612 字节，总申请 80532 字节，不含 malloc 管理开销。相对旧 262144 字节预留少 181612 字节；这不是整场游戏峰值，也不包含游戏/ROM cache。片头、进入新征程剧情、长按退出恢复桌面通过。
- 冷函数加载必须发生在 IRAM 解释核写回并返回外部 C 之后，随后重试同一客机 PC；不能在 IRAM 调用栈仍活跃时直接 malloc/free 并依赖 SDK 恢复一定成功。现有其他 ROM/SDK 回调的恢复约定没有因此被宣称全面验证。

### 外置手写模块实现（2026-09-08，开发中，不交付）

- `--firmware-native-rom E.BIN` 构建手写函数包，而非旧逐指令 AOT。内部构建生成配套 EXE 和 `GAM4980.NAT`；不再把单独 EXE 当作完整交付。
- GNAT format 4 / ABI 4 / FIRMWARE flag 0x10：match 的第二字段是原函数字节数，不能作为旧 AOT 索引。打开包时校验真实 ROM 字节；发布入口时按物理 bank 校验，不再调用旧 AOT 匹配器。
- 六个模块源文件：`firmware_native_bank.c`、`firmware_native_multiply.c`、`firmware_native_divide.c`、`firmware_native_compare.c`、`firmware_native_runtime.c`、`firmware_native_memory.c`。目标编译检查零重定位；函数只通过客机内存回调和上下文访问状态，不直接调用 9288 SDK。
- bank 范围设置／读取、bank 查询／切换及恢复入口：9 万组随机对照；算术 219072 组（字节乘除分别穷举 65536 对输入，有／无符号 16 位乘除各 20000 组，另含公共无符号别名入口）；运行库 14 万组（临时地址、long 运算／取负／按位取反、浮点符号取反、比较、间接调用、8/16/32 位移位、交换、逻辑非、类型转换、指针乘三、参数入栈和四字节存储）。算术及内存函数另验证预算不足不修改任何状态。后续扩大覆盖时必须继续跑测试。
- 32 位移位不能只根据函数名重写：本 ROM 的 `$D93F` 在检查负数前执行 `LDY #$0b`，N 被清除，普通移位数实际走逻辑右移分支；但超位宽时仍按原始符号填充。零移位时，三种 long 移位都复制到临时区而不更新 oper1 指针。已依据原字节码的完整状态对照保留这些行为，未擅自“纠正”固件。
- 实际 E.BIN 的 `$E901` 是 `JMP $F5BD`，`$E904` 是 `JMP $F68A`。因此 `SysMemcpy` / `SysMemcmp` 不能使用 SDK map 的 `$F3BD` / `$F48A` 直接绑定。原生内存模块已按真实入口实现两函数；4000 组重叠、跨页、首差异位置、零长度和预算拒绝对照通过。`SysMemcpy` 按原固件具有 memmove 语义，`SysMemcmp` 的比较方向和结果状态遵循原固件，不套用宿主库的参数顺序。
- 自动测试核查每个手写入口都有函数指纹、IRAM 分派和对应页的 loader link，避免只更新函数实现漏接入口。跨页的函数体可以由一个完整指纹保护，但另一页上的独立入口必须有该页的链接记录。
- 共享页不能采用“第一个模块获胜”：bank 模块和内存模块同时占 `$F5` 页，原逻辑会遮住 `SysMemcpy`。共享的手写模块页使用完整物理 PC 路由，唯一模块页仍直接调用；不扩大 IRAM。调试符号 `native_module_firmware_route_mask` 记录实际成功执行过的共享页模块位，供 QMP 检查，不能把仅加载成功视为调用成功。
- 乘法直接使用宿主乘法，最后有效 ADC 的 C/V 用代数推导；不是复制原 8/16 轮运算。
- 动态桥保留 V2 解释核，避免旧 shadow 模式超出 IRAM。手写模块只在 bank-qualified 入口尝试，不在同页每个分支尝试。
- 已发现并修复一次“包加载成功但函数完全未调用”的错误：入口发布仍把长度当旧 AOT 编号。修复后的模拟器实测模块调用从 18736 增到 28780，能够进入开场剧情；这不是性能结论。
- 当前内部模拟器为 6281 QMP 的独立进程。六模块版本（含有符号 16 位乘除）已验证《伏魔记》开场剧情及长按退出回桌面，《魔塔之怀旧终曲》已验证标题与开场剧情。共享页路由成功位为 0x1d（bank、multiply、divide、compare），不能据此声称 memory 已实际调用。模拟器只用于正确性，不用于真机性能结论。
- 后续新增 `$DCAB` / `$DCB1` 无符号字节／16 位取模，增加 40000 组状态及预算不足对照，算术累计 259072 组通过。保留原函数零除数行为以及内部除法产生的必要结果，不能直接用宿主 `%` 的未定义零除行为。独立六模块包编译零重定位通过；新增入口尚待下一轮目标端合并回归。
- 随后补入有符号字节乘法 `$D65B`、除法 `$D39B`、取模 `$D5C6`（各穷举 65536 对输入），以及有符号 16 位取模 `$D5DC`（20000 组）；原算术测试累计 475680 组。32 位栈参数乘法 `$D201` 单独增加 20000 组完整状态／短预算对照，使用宿主 32 位乘法，保留返回临时区及 ABI 栈内容。上述模块继续通过零重定位编译与入口审计，未宣称全部固件已完成。
- 长整数后续覆盖 `$D0A8`、`$DC83`、`$DCF7`、`$DCC8`、`$D6F5`、`$D435`、`$D604` 和内部 `$D752`：有／无符号乘除及取模与调用者参数布局一并替换。独立长整数测试共 180000 组，含随机上半部分余数、零除数、最小负数和跨页资源；预算不足不得写状态。
- 新增第七个 `firmware_native_float.c` 模块，覆盖比较 `$E039` 和接口 `$E51C`，增加 40000 组，`firmware_native_long_multiply_test.c` 累计 220000 组。它按固件编码排序，不套宿主 IEEE NaN／有符号零规则。浮点加减乘除及转换仍未完成。
- 《三国霸业6980-方案一》在干净启动时出现花屏；同一 EXE 删除 NAT 加载路径的内部对照同样花屏，不能归因于新增手写模块，但兼容性未通过。两份对照镜像均仅在忽略的 build 目录，不含于交付包。
- 除法模块不能引用编译器的 `__udivsi3` / `__umodsi3`：独立模块没有这些链接目标。采用内联宿主整数算法，构建继续要求零外部重定位。16 位除法的周期采用当前 65C02 核的索引移位行为，不能直接套 py65 普通 6502 的周期；SP 小于 5 时原函数存在不回绕的 absolute-X 访问，当前保守回退，尚不属于 resource-only 完成状态。
- 仍未完成全部 E.BIN 函数替代，不能开启 resource-only、不能正式发布，也不向用户交付中间 EXE/NAT。

### 新增 bank 原生函数（2026-09-07）

- `$F475`：连续 bank 映射写入，宿主循环直接完成寄存器更新，不再分派原函数的 6502 指令；接入 `$F48B` 预算回退后的循环恢复入口。
- `$F457`：读取选定 bank 的映射到调用者缓冲区，直接执行参数读取和结果写回。
- 使用实际 E.BIN 函数字节双哈希确认版本。范围写入不得改写当前 F 执行窗口；特殊参数/输出别名走原路径，避免改变后续取指语义。
- `tests/firmware_hle_bank_range_test.c`：三个入口各 10000 组随机 CPU/RAM/bank 全状态对照；每入口前 16 组遍历从 1 到完整函数周期的预算，验证回退和续执行。
- 测试参数不能写到 `$0300` 页：该页是固定 ROM 映射，写入被忽略。可写测试缓冲区从 `$0400` 起。
- 这两项是实际函数替换，但不代表 E.BIN 已全部原生化。真机性能收益尚未测量。
- 模拟器冒烟：进入《伏魔记》开场剧情，长按退出键回到桌面；未验证完整系统菜单结束游戏链。此后新增的参数物理别名防护通过宿主差分测试，最终 EXE 已重新编译。

- 目前 E.BIN **仍有代码执行依赖**，不是纯资源包。
- 258 个 SDK 公共符号不是 E.BIN 所有内部函数的完整清单；SDK 地址绑定也必须与实际 ROM 核对。
- 离线原生运行库可复用算法，但 ABI、客机 RAM、设备模型要适配；其中简化实现不能视为完成，例如当前 `SysGetSecond` 返回固定 0。
- 不得用返回 0 的空函数让未实现 API 看似成功。

## 完成门槛

1. 公共 API 与运行库函数逐项确认调用约定、ROM 入口、输出和必要副作用。
2. 提取 E.BIN 的只读资源访问方式；保留游戏直接读取资源地址的兼容映射。
3. 在统一表接入每个原生实现，验证真实调用者需要的行为。
4. 等待类 API 保留等待语义；绘图/计算允许原子执行时不强制逐指令周期复刻。
5. 未覆盖入口与剩余固件执行必须可见；它们归零并通过游戏回归后才能启用 resource-only。

目前没有启用会使现有游戏失败的强制 resource-only 模式；清单输出明确为 `resource_only_ready=false`。
