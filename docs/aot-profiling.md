# GAM4980 AOT 热点分析

## 目的

9288 真机只有约 48 MHz 主频，而 GAM4980 核心需要维持 4 MHz 的 65C02
客机时钟。继续缩短单条指令解释路径仍有收益，但要取得倍数级提升，需要把一部分
高频基本块提前转换成 S1C33 原生代码。

不能把两个 2 MiB ROM 从头到尾盲目当作代码：GAM4980 使用 4 KiB 动态银行
映射，ROM 中还混有字库和数据。现实现先记录实际取指的“物理 PC + 虚拟 PC”，
再把完整 8000 帧轨迹中出现的 E.BIN 代码块全部离线转换；未出现的固件路径和
游戏 Flash 仍可安全回退到解释器。

## 分析键

工具在每条 65C02 指令取指时记录：

- 16 位虚拟 PC；
- 经当前银行表转换后的 24 位物理 PC；
- 操作码。

基本块在控制转移、非连续虚拟地址、非连续物理地址处切分。统计键同时包含物理 PC
和虚拟 PC，不能只使用虚拟 PC：同一个 16 位地址在银行切换后可能指向完全不同的
代码。也不能只使用物理 PC：同一物理代码映射到不同虚拟地址后，PC 相对控制流的
结果可能不同。

该钩子受 `GAM4980_ENABLE_PROFILING` 控制。9288 的正常构建没有定义这个宏，
因此真机解释器不会增加逐指令分支或回调。

## 使用

```bash
gcc -std=gnu11 -O2 -Wall -Wextra -Werror \
  -Wno-unused-parameter -DDL_DOWN -D_RLS_ \
  -DGAM4980_ENABLE_PROFILING -Isrc \
  tools/gam4980_aot_profile.c src/gam4980_core.c \
  -o build/gam4980-aot-profile

./build/gam4980-aot-profile \
  --frames 5000 --start-frame 3300 \
  --key 3300:enter --key 3480:enter --key 4380:enter \
  --frame-output build/aot-final-frame.pbm \
  --output build/aot-profile.csv \
  应用/数据/游戏/gam4980/8.BIN \
  应用/数据/游戏/gam4980/E.BIN \
  /path/to/你有权使用的游戏.gam
```

选项：

- `--frames N`：总共运行的 60 Hz 客机帧数，默认 3600。
- `--start-frame N`：从哪一帧开始记录，可跳过启动动画。
- `--key FRAME:KEY`：在指定帧注入按键，可重复。当前支持
  `enter/exit/esc/up/down/left/right/space/menu/0-9`。
- `--top N`：终端显示前 N 个块，默认 30。
- `--output FILE`：完整 CSV 报告路径。
- `--frame-output FILE`：把最后一帧写成 160×96 PBM，便于确认轨迹实际到达
  的游戏画面。

游戏文件只在本机读取，不会被复制进报告、仓库或发布包。

## 《伏魔记》开场阶段结果

使用用户提供的《伏魔记》版本，先运行到主菜单，再记录第 3300～5000 帧并注入
三次 Enter。一次实测得到：

| 指标 | 结果 |
|---|---:|
| 动态 65C02 指令 | 22,574,330 |
| 不同映射基本块 | 890 |
| 覆盖 50% 所需块数 | 13 |
| 覆盖 80% 所需块数 | 46 |
| 覆盖 90% 所需块数 | 78 |
| 覆盖 95% 所需块数 | 119 |
| 覆盖 99% 所需块数 | 213 |
| E.BIN 系统 ROM 指令占比 | 99.56% |
| 游戏 Flash 指令占比 | 0.44% |

这是动态轨迹，不代表所有游戏和所有场景，但已经证明热点高度集中，而且
绝大多数位于固定的 E.BIN。短轨迹的前 46 块覆盖约 1,806 万条指令（80.01%）；
正式实现进一步使用从启动开始的 8000 帧完整轨迹重新选块，避免漏掉初始化和
绘制阶段的长循环。当前 46 块在完整轨迹的 128,052,365 条指令中执行
92,204,152 条，占全部指令 72.00%、E.BIN 指令 79.05%。这些块可以在多款游戏
间复用，也不需要把任何 `.gam` 绑定到程序。生成器保留了更多候选块并提供
`--limit`、`--skip` 和 `--formal-limit` 调优选项；简单增至 48、64 或 78 块
均因代码尺寸和分派成本而变慢。该段保留为早期热点方案的历史结果；当前正式
构建已扩展到下述完整 E.BIN 轨迹 AOT。

## 两个 BIN 的完整轨迹结论

从启动开始运行 8000 帧、按主菜单和开场剧情路径注入 Enter 的无加速画像得到：

| 指标 | 结果 |
|---|---:|
| 动态 65C02 指令 | 128,049,964 |
| E.BIN 动态指令 | 116,630,470 |
| E.BIN 物理 PC + 虚拟 PC 基本块 | 926 |
| 8.BIN 取指块 | 0 |
| 正式离线翻译的 E.BIN 块 | 926 / 926 |

`8.BIN` 在当前固件中是字库/数据 ROM，画像中没有任何 6502 指令从它取出，
所以没有可翻译的 CPU 代码；继续优化它应针对数据读取缓存，而不是生成原生
指令。`E.BIN` 的 926 个已执行映射块则全部编进 KF2。这里的“全部”严格指这份
完整动态轨迹，不声称覆盖 2 MiB 文件中从未执行、也可能只是数据的每一个字节。

## 当前 AOT 实现

生成器 `tools/generate_aot_ebin.py` 解码固定的 E.BIN 热点，并生成
`src/s6502_aot_ebin_generated.h`。正式构建默认启用，可用 `--no-aot`
构建纯解释器对照版。实现遵守以下约束：

1. 以“物理位置 + 虚拟入口”查找，进入前校验映射和 ROM 版本。
2. 返回下一虚拟 PC、累计客机周期和可能改变的 CPU 状态。
3. 在间接控制流、中断检查点、银行寄存器写入和可能修改代码的写操作前退出。
4. 未转换或校验失败时无条件回退到现有解释器。
5. 生成文件记录 E.BIN SHA-256，每个块首次执行时逐字节校验签名；
   块字节或当前物理映射不匹配时立即回退到解释器。
6. 已完成等价验证的原始 47 块可在安全边上直接衔接；画像新增块在基本块边界
   回到调度器，以保留 IRQ、Timer、halt 和银行映射检查的原始顺序。同一虚拟
   PC 对应多个物理 bank 时，调度器依次校验所有固件变体。
7. 常量零页地址直接访问 RAM；使用固定 `0x2000` RAM bank 的块还会在入口
   校验 bank 2 映射后走直访。映射不符合假设时仍回退到普通解释器。
8. 原生超块全部进入 KF2 的静态 `.text`，不申请 JIT 缓冲区，也不占用约
   1.5 MiB 的可用连续堆预算。

### 6502 IR、延迟标志和热点链

离线生成器现在先把每个 E.BIN 基本块解码成 `InstructionIR`，显式记录每条
指令对 N/Z/C/V/I/D 等状态位的读取和写入，再从块出口反向计算活跃状态。
块出口仍保守地把全部状态视为可观察，PHP、PLP、RTI、旋转、ADC/SBC 和条件
分支也保留各自的隐式依赖；只删除同一块内确定会被后续结果覆盖的标志写入。
N/Z 作为一组写回，以免为了少更新一个位反而增加 S1C33 指令。

926 个块共含 7,326 条静态客机指令，其中 4,549 条写状态；IR 证明 3,152 条
写入完全死亡，另有 366 条只需保留部分状态。A/X/Y/SP 和尚未写回的 CPU 状态
一直保存在 `s6502_exec` 的局部原生值中，不在每个客机操作后复制回 CPU 结构。

跨块链接仅在生成顺序前 150 个画像热点之间启用，并且每条边仍检查 cycle
预算和 halt；物理映射不唯一、bank 条件不满足、来源可能改映射或目标属于任一
固件 HLE 入口时返回正常分派器。曾验证过把全部 926 块互相链接：机器状态仍
等价，但 `s6502_exec` 增至 351,018 字节且 S1C33 编译时间明显变长，因此没有
保留这种全链方案。

同一诊断构建中，`s6502_exec` 从 309,204 降到 293,642 字节，减少 15,562
字节（5.03%）；KF2 从 640,817 降到 625,257 字节。以无 AOT 的 31,392 字节
解释器和 S1C33 的 2 字节指令字做静态估算，AOT 增量约从每条客机指令 19.0
条原生指令字降到 17.9 条。该值包含分派、校验、模板和诊断路径，只用于比较
代码生成，不等于运行时 retired-instruction 比例。

电脑端 O0 配对测试的同一 8,000 帧轨迹从平均 1,884.63 ms 降至 1,483.00 ms，
约 1.27 倍；这只证明热点链在执行层面有收益，最终性能结论仍使用 9288 真机
日志，不能用桌面 CPU 结果代替。

### 第二层 IR：16 位加减短语融合

进一步对画像中的基本块做指令短语统计后，生成器会把可证明为直接 RAM 访问的
`CLC/SEC + LDA + ADC/SBC + STA + LDA + ADC/SBC + STA` 合并为一个 16 位
小端加减操作。融合仍精确保留低字节后高字节的写入顺序、最终 A 和状态位、
22 个客机周期；若 6502 处于十进制模式，入口立即回退到原解释器。因此这不是
按游戏结果近似的 HLE，而是同一段 6502 指令的等价 IR 降低。

926 个块中有 31 块命中，共融合 33 个短语（30 个加法、3 个减法）；按现有画像
估算约覆盖 3,881,840 次动态短语。相对第一层 IR，S1C33 的 `s6502_exec` 从
293,642 降到 286,992 字节，减少 6,650 字节（2.26%）；带诊断的 KF2 从
625,257 降到 618,609 字节。与做 IR 前的 309,204 字节相比，`s6502_exec`
累计减少 22,212 字节（7.18%）。

正确性除 8,000 帧完整状态回归外，还穷举验证了加法和减法各 65,536 个输入，
共 131,072 组；周期、寄存器、状态位和被写 RAM 均与逐指令解释路径一致。

以下候选也做过等价实现，但没有保留：

- 跨基本块延迟写回 N/Z/C/V/I 会增加 S1C33 寄存器压力，KF2 反而增加；
- 显式批量累计固定周期与 LLVM 已有优化重复，KF2 增加 488 字节；
- `DEC + LDA 同地址 + CMP #0` 的短语融合覆盖约 155.9 万次动态执行，但
  LLVM 已自动生成相同 S1C33 机器码，KF2 逐字节不变；
- CMP/CPX/CPY 到条件分支的 SSA 条件前递在桌面端成立，但 S1C33 KF2 增加
  352 字节。

这些结果说明是否保留 IR 优化必须以 S1C33 机器码和真机日志为准，不能只看
桌面编译器的耗时变化。

当前 926 块诊断构建的 9288 KF2 为 618,609 字节，其中 `.text` 为 355,848
字节；`.bss + scratch` 约 225 KiB。AOT 代码和签名都在 KF2 的静态段中，不申请约
1.5 MiB 的连续堆，也不在启动或载入游戏时做 JIT 编译。8000 帧等价回归中，
进入固件 AOT 的画像指令为 49,813,864 条（另有 HLE 直接替代的固件循环）。
这些计数说明覆盖范围，不是真机加速比例；性能结论仍以同场景真机测试为准。

## 正确性验证

- 5000 帧无输入轨迹的最终帧缓冲校验和一致。
- 开场剧情按键轨迹与 8000 帧长轨迹的 CPU、RAM、Flash、映射、定时器与 LCD
  全状态哈希和纯解释器完全一致。
- 人为修改一个热块字节后，AOT 正确拒绝该块并回退到解器，全状态仍一致。
- 926 块 S1C33 KF2 已在 `bbk9288-emulator` 走完文件选择、主菜单、场景、开场剧情、
  游戏正常退出与长按退出，2× 几何校验通过。
