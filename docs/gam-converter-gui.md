# GAM → 9288 可视化原生转换器

这是现有 PC 原生重编译器的 Windows 桌面界面，不是播放器的文件选择界面。
转换调用 `tools/compile_gam_native_9288.py`，生成独立的 S1C33 / KF2 程序。
整个过程在本机完成，不上传 GAM、图片或生成产物。

## 使用

1. 双击 `build/GAM-to-9288-Converter.exe` 打开界面。
2. 点击“选择 GAM”，选择自己有权使用的游戏。界面显示标题、体积、头部代码段长度和入口。
3. 修改“程序名称”；右侧实时预览桌面名称和图标。
4. 可点击“替换图标”选择 PNG、JPEG、BMP、ICO 或 WebP。透明背景合成到白底，
   保持纵横比，转换为四灰阶，保留 9288 原有边框；预览与最终 EXE 使用同一转换结果。
5. 确认输出位置，点击“一键转换为 9288 EXE”。界面显示真实编译阶段、耗时和完整日志。
6. 完成后点击“打开输出目录”。将生成的 EXE 复制到 9288 的 `A:\系统\程序\`，在“娱乐”中启动。

名称写入 **KF2 内部名称和应用窗口标题**；默认输出文件名也随名称更新。
9288 桌面标签取 EXE 文件名，所以若另行改了输出文件名，桌面标签也会变化。
9288 名称字段采用 GBK，最多 15 字节（一般为 7 个汉字或 15 个英文字符），不支持 emoji。
图标包括 40×40 和 16×16 两份。当前没有从 GAM 内嵌数据提取任意游戏图标的功能。

生成的游戏 EXE **不是 Windows 程序**，请勿在电脑上直接运行。
同目录还会生成 `.elf`、`.map`、`.report.json`，用于调试与校验；真机只需 EXE。
独立 EXE 已包含游戏资源，不依赖原始 GAM、8.BIN、E.BIN 或 GNA 模块。

## 编译环境与启动器

当前 EXE 是本机启动器，不是已打包全部编译工具的便携版。请保持它位于本工程的
`build` 目录，并保留源码、Python 和编译依赖。移动到另一台电脑需要重新配置环境。

- Python 3.10+，带 Tkinter 和 Pillow；本机使用 `D:\ProgramData\miniconda3\pythonw.exe`。
- 9288 SDK：本机默认 `D:\Downloads\app_env_9288`，不使用 9588 SDK。
- 本工程 ABI 修正版本的 S1C33 LLVM 工具链：默认 `build/llvm-s1c33-host`。
- PC `gcc` 位于 PATH，用于离线准备启动状态。
- 本工程的 `应用/数据/游戏/gam4980/8.BIN`、`E.BIN`。
- 当前前端仍依赖 `D:\Downloads\BBK旧A系列C语言开发包\dwn\test.map`。

“编译环境”窗口可以修改 SDK 和工具链路径，保存到 `build/converter-settings.json`。
其他依赖暂未做成可配置的便携安装包。

重新生成 Windows 启动器：

```powershell
python tools/build_converter_launcher.py
```

也可直接运行 `python GAM-to-9288.pyw`。启动器启动失败的信息在
`build/converter-startup.log`。

## 日志、取消与输出保护

- 每个界面任务使用独立的 `build/converter-jobs/job-*/`，完整日志为 `conversion.log`。
- 窗口保持响应，支持取消；仅停止本次编译及其子进程。
- 编译、链接和体积检查完成前不会替换旧 EXE；已存在的输出需要确认后覆盖。
- 操作系统文件锁防止两个转换任务同时使用前端共享的启动状态生成步骤。
- 成功后校验 EXE 的 SHA-256 与报告一致。中间目录保留用于排错，不自动清理用户文件。

## 兼容性边界

这是功能验证中的 C6502 GAM 编译器，不保证任意 GAM 或所有游戏流程都兼容。
未知的运行库接口、未恢复的调用或超出当前 1 MiB 限制会报错，不静默退回解释器。
“转换完成”只表示原生编译、链接和输出校验成功，不等于游戏全流程或真机性能验证。
游戏兼容性现状见 [原生编译器说明](gam-native-compiler.md)。
