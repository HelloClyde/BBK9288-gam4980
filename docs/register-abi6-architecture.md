# ABI 6 合并架构优化

本轮围绕共享 ABI、连续原生执行、解释核和首次加载实现，不代表所有代码路径已没有优化空间。

## 原生函数入口

`tools/native_register_codegen.py` 从已按入口常量专门化的函数生成私有入口。入口读取 R4..R11 的 A/X/Y/SP/PC/P/cycles/instructions，内联原有已验证函数体，再以这些寄存器返回；R12 返回接受结果。R0/R1/R14/R15 保持调用者约定。

142 个 NAT 函数均提供私有入口。原有七个手写叶函数保留更紧凑的实现，其余由生成器提供。原 C 入口保留作对照与安全回退。ABI 6 防止旧版 EXE 未提供调用保护时误加载。

注意：这是**寄存器边界 ABI**。编译器可在函数内部重新分配寄存器、产生栈溢出存取；图形函数有地址逃逸的局部 context，不能宣称整个函数体一直把所有状态固定在同一寄存器，或完全没有内存读写。

所有对象须通过无重定位审计。局部 context 禁止产生外部 memcpy 依赖。NAT 同时保留两类入口，因此包及常驻代码会增大，仍按已有函数驻留/淘汰机制管理。

## 连续执行与回退

- 私有入口缓存扩至 256 项，精确校验虚拟 PC 和实际 bank，冲突由 C 入口重新发布，绝不把冲突当命中。
- 已驻留的原生后继保留寄存器状态，省去重新装载 opcode 表和通用 dispatch bitmap。保留预算与关机检查，不跨客机事件截止点。
- 私有函数执行期间增加 active_calls，回调不能淘汰仍在执行的代码。控制边界不再需要的 saved_fetch 槽保存 pin 指针，未引入解释循环栈溢出。
- 私有函数拒绝后直接转解释慢路径，避免立即通过 C 包装重复尝试同一合约。
- C 后备路径增加带物理地址验证的入口缓存，冷缓存、bank 变化、失效和 cooldown 保留完整检查。

## 解释核与加载

- 九种零页读取使用专用寻址；特殊 DATA/bank 地址仍回退。
- LDA abs,X/Y 保持取指指针，不再为地址计算保存/恢复该指针。保留跨页附加周期与 16 位回绕。
- 编译器模板生成 256 项首字节索引，首次扫描跳过不可能匹配的模板；不改变模板优先级、选择顺序、CFG/HLE 合约。
- 保留 GAC 重复启动缓存及失效重建。

## 性能与验证口径

共享入口时间计入 IRAM 阶段；nat_sample_* 仅覆盖 C 后备入口，不得误判其数量下降为函数消失。
没有新真机结果前，不把模拟器速度或代码尺寸换算为真机提升百分比。

## 后续：context 初始化与入口生命周期

2026-09-08 后续候选保存在 `build/context-abi6/`，不覆盖上述基线。

- 非文字生成入口按字段初始化全部 context：八个 CPU 字段直接来自寄存器，其余字段来自环境，避免先复制旧 CPU 状态再覆盖。测试将字段表与 C 结构严格对齐，防止新增字段未初始化。
- 文字入口保留原来的内联复制：尝试统一改法后，两个文字入口总共增大 824 字节。代码尺寸并不是耗时，但在缺乏正收益证据时不引入该变化。
- 最终 NAT 从 325866 变为 325434 字节；图形函数两类入口总代码 76330 → 75878，文字 46838 不变。这些是静态尺寸，不是真机速度提升。
- 修复释放顺序：只有释放成功后才清除属于该 allocation 的私有入口。执行中拒绝释放、heap free 失败不再让快路径失效；另一 bank 发布的同虚拟 PC 入口不被误清。
- 18 组 S1C33 等价探针通过；最终 NAT 的两组 loader 测试通过，新增执行中/释放失败/另一 bank 同 PC 的入口生命周期断言。
- 首次目标探针超时来自旧测试 NAND 的开机密码界面；换用上一轮游戏正常退出的镜像后通过，没有修改模拟器或放宽等价断言。

该阶段仍未实现整个函数体固定寄存器、双入口共享函数体、私有调用热度淘汰策略，以及新一轮宿主耗时归因；后续进展见下一节。

## 共享函数体、私有入口热度与图形 context 消除

最终候选 `build/shared-abi6/`：

- **142 个函数单一实现**：C 入口是 PC 相对调用适配器，IRAM 直接进入同一份私有函数体。原来的七个手写叶函数仍使用手写代码。每个包内对象验证无重定位；C 入口从 R6 取 context、保持 R0..R3、返回实际客机周期增量，而不是把私有入口的布尔值误当周期。拒绝时返回零且不回写客机状态。手写叶函数的原 C 入口诊断计数由适配器保留。
- **热度感知淘汰**：私有入口在 active_calls 相邻的 register_referenced 字中设置引用标记。只有发生淘汰选择时才消费标记并刷新时间戳，避免每次私有调用都更新全局时钟。正在执行、固定驻留的函数仍不可淘汰。此为 second-chance 近似热度策略，不是精确调用次数 LRU。
- **消除具体的 context 逃逸**：out-of-line 行输出函数改为只接收 RAM 指针、客机 PC 和 graphics services，而不是整份 CPU context。保留实时 framebuffer 读取和既有键盘 poll 规则。
- 目标反汇编相对最初 ABI 6 审计对象：图形 $5C5D 栈帧 69 → 44 个 32 位字，文字 $650F 60 → 42 个字（均不包含公共 pushn）。仍有算法局部量和回调所需 spill，不能称为全程固定寄存器/零栈访问。

尺寸（与上一轮 context 版对比）：NAT 325434 → 190934 字节，减少约 41%；manifest 24688 字节不变，最终代码 165266 字节。EXE 682961 字节，IRAM 5332 字节。原 C 函数仍保留在源代码中作等价参考，但不再随共享包重复装入。

- 编译生成私有入口、手写私有入口两种目标探针均通过 18 组；新增 C 适配器 CPU/RAM/周期返回值、手写入口诊断计数及引用位断言。
- 最终 NAT 的 loader 两组测试通过，包含私有热函数获得第二次驻留机会、不淘汰 active 函数、释放失败保留入口、同 PC 不同 bank 不误清入口。
