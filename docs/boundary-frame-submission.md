# 绘图边界提交实验

保留 FULL-SUBMIT 的完整 320×240 物理屏幕重写，NAT 只写客机显存。本轮改变提交时机，不改变客机执行、IRQ 或 bank 语义。

- NAT `SysPicture` 入口记录绘图状态；已识别的行尾完成整屏复制时立即保存 1920 字节快照，避免同一执行批次的后续绘图污染完成帧。
- 批次结束优先提交该快照；其他路径在客机等待、显存连续两批不变且安静至少 6/256 秒时提交。
- 未识别结束点的连续绘图最多等待 64/256 秒，随后超时提交。这是有界启发式，不是已证明的整地图事务边界，仍可能显示局部进度。
- ROM/系统恢复只重画上次已提交画面，不把待完成显存提前展示。
- 新增两份 1920 字节数据：完成图片快照与最后提交画面。IRAM 执行核不变。

日志 `presentation_boundary_version=1`，分类记录 `presentation_picture_commits`、`presentation_wait_commits`、`presentation_quiet_commits`、`presentation_timeout_commits`。`render_updates` 计显存捕获变化；`screen_submissions` 才是实际屏幕提交次数，两者不再同步。提交耗时除以提交次数，不能除以客机推进帧数作为单次提交耗时。

图形服务 ABI 从 2 升为 3，EXE 和 NAT 必须配套更新。此包不含游戏、BIN 或 SDK。

验证：策略测试通过，独立展开模型 1612 例通过；模拟器伏魔记片头与剧情运行，完整图片完成提交实际命中 29 次；屏幕与最后已提交快照 76800 像素全部一致；Esc 退出返回桌面。剧情仍出现超时提交，不能宣称所有游戏路径都消除逐块呈现。速度和观感仍需真机确认。
