# EXEC-TAIL：解释核公共开销优化

相对 `GAM4980-FETCH-KEEP.exe` 的本轮变更：

1. ADC/SBC 公共运算入口保存宿主取指指针，结束后恢复，不再重新查代码页。绝对 X 和间接 Y 入口在覆盖 R2 之前保存，避免保存错误的页惩罚临时值。
2. LDA 绝对索引、LDA/ADC/SBC/STA 间接 Y、STA 绝对 X 也使用该恢复路径。保留十进制模式回退、特殊零页寄存器过滤、跨页周期和 LCD 写入规则。
3. 普通完成尾部内联下一次 opcode 分派；N/Z 完成路径直接落入完成尾部，减少公共跳转。不取消 PC 边界检查。
4. BNE/BEQ/BMI/BPL 直接查询延迟 N/Z；仍需在 PHP、状态回写等观察点物化状态。没有把客机 flags 长期寄存在易被寻址/调用破坏的宿主 PSR。
5. C 侧 IRAM 重入循环只在调用开始时发布稳定的 ABI 表地址、回调和日志指针。仍逐次刷新预算、shadow 选择和 native 模块选择；bank 切换更新的页表内容仍实时可见。没有删除必要的客机状态同步。

## 验证结果

- 128 项 Python 单元测试通过；`git diff --check` 通过。
- IRAM 审计通过：5284 字节，低于已验证的 5832 字节窗口；较 FETCH-KEEP 增加 60 字节。
- 基线与新版目标探针均 14/14 组通过。其中新增两组各遍历 256 个输入：连续 ADC/SBC、跨页间接存取、延迟标志分支；以及全部 256 种初始状态字下的分支判断。
- 新版不带单指令 trace 时，探针正常完成并返回桌面。
- 正式游戏 EXE 的新 NAND 镜像经过 SHA256 核验；模拟器文件选择、启动画面及《伏魔记》开场剧情显示正常。本轮没有完整游玩回归。

## 性能证据限制

为比较完全相同的探针工作量，增加了 `--engine-source` 基线构建选项、隔离镜像运行脚本及 trace 对照分析器。

单指令 trace 模式出现两类异常：一次在 IRAM 执行前停止于 0x02401830；另一次目标检查已全部通过，但返回桌面时停止于低地址。trace 中也有未成对的 IRAM 入口/返回，比较脚本拒绝输出收益数字。不能把这些记录当成可靠的同路径性能测量，也不能据此认定异常来自游戏代码；无 trace 的目标与游戏测试通过，但 trace 异常原因尚未确定。

因此本版没有声称整体提速百分比或新的游戏指令比。真实收益需要同场景真机日志验证。
