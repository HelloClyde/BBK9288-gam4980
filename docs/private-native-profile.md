# 私有 NAT 入口耗时归因（2026-09-09）

## 修复的盲区

原 `nat_sample_*` 只统计 C 后备入口。共享寄存器 ABI 从 IRAM 直接进入 NAT 时，没有经过该计时桥，耗时混入 `host_exclusive_iram_ticks`。这会漏掉真正运行的热点，不能根据旧函数榜推断 NAT 不耗时。

本轮保留现有每 16 个执行片段采样一次的策略。采样片段使用镜像入口表，把直接入口指向外部 RAM 的计时包装；非采样片段仍使用原入口表，IRAM 指令和 NAT 函数体不变。不把调用退回解释器，也不改游戏执行语义。

入口发布、重新发布、释放和重置同步更新两张表。仍由原 IRAM 路径校验 PC/bank 并 pin 活动函数。包装保存 R0..R15，在栈上保存目标地址和嵌套计时 token；实际执行同一个原生寄存器函数体，返回后完整恢复其输出状态。

## 日志

- `native_function_profile_version=2`
- `nat_function_profile_c_bridge_only=0`
- 每组 `nat_sample_pc/attempts/accepted/exclusive_ticks` 现在包含采样到的 C 入口与私有入口。
- `nat_sample_private_attempts/private_accepted` 单独指出其中的私有调用数量。这两个字段是次数，不是时间。
- 图形、文字、其他 NAT 时间分别归入对应的宿主阶段，不再重复计入 IRAM。调用中的已标记 I/O 或其他嵌套阶段独立结算。

`tools/analyze_host_profile.py` 保持按累计独占 ticks 排序，自动识别新旧口径。

## 误差与开销

仍使用 256 Hz 时钟（约 3.9 ms）。短调用可能为零 ticks；固定步长采样也可能与游戏执行节奏相关。逐函数榜是采样内分布，不是完整会话精确占比，不能用 RTC 会话时间作其分母。

采样时包装和读时钟有开销，不进行未经校准的“空循环扣除”。函数计时包含边界包装的一部分成本，极短函数的排名要谨慎解释。关闭调试或处于非采样片段时不会进入该包装；这不等于宣称整个程序绝对零新增开销。

额外静态数据：镜像入口表 4096 字节，私有调用计数 1536 字节，均在外部 RAM，不占 IRAM。包装栈框架为 112 字节（S1C33 的 SP 立即数以 word 为单位），另有正常调用返回地址及 C 辅助函数栈。

## 为什么通用块融合尚未完成

已有的是已知语义模板、部分指令融合、原生后继直连，不是任意基本块都能融合的运行时翻译器。

真正通用化还缺：

1. 以实际 bank/物理代码身份建立区域 CFG，不能只以虚拟 PC 定位。
2. 代码写入、映射变化、缓存淘汰时可靠失效，并保护执行中的代码。
3. 为每个可能的慢路径、预算结束、间接跳转建立退出映射，恢复正确 PC、寄存器、延迟 flags 和已提交写入。
4. 跨块活跃性分析、寄存器分配和代码空间预算，避免消除分派却增加大量状态保存。

它有难度，但不是不可做；之前实现的是局部优化，没有完成上述整套机制。优先可做同 bank、只读代码、单入口、明确出口的受限区域，再逐步扩大。不能把这轮计时补全说成已经实现通用块融合。
