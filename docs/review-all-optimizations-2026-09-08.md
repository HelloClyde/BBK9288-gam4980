# 架构优化后续实现（2026-09-08）

这次覆盖五个方向，但不表示所有固件函数都已改用寄存器 ABI，也不表示真机已经满速。性能结论必须来自同一路线的真机对照。

## 1. 原生函数共享寄存器 ABI

NAT 的 C 入口保持兼容，另提供 7 个寄存器入口：D586、D596、D5A6、D5B6、DDA7、DDE4、DDEE。它们分别处理临时结果地址、操作数交换和布尔取反。

- R4–R11 保持 A/X/Y/SP/PC/P/周期数/指令计数；R0/R1/R14/R15 不变。
- 只使用普通 RAM，无文件系统、bank 修改、I/O 或可重入回调。
- IRAM 控制边界按 PC 查 64 项稀疏索引，比较当前 bank，再调用已加载入口。
- 接受时不保存/恢复整份 CPU 上下文；十进制模式、周期预算不足、模块未加载、bank 不符均保留原路径。
- 函数卸载时撤销指针，关闭 NAT 时清空索引；代码仍由 NAT 函数粒度加载，不搬入 IRAM。
- 索引占外部 RAM 1024 字节；IRAM 为 5516 字节，小于已验证的 5832 字节窗口。
- 其他函数仍使用原 C ABI，不能把本次说成“全部 NAT 已寄存器化”。

`tools/native_register_abi.py` 是这些原生叶函数的源代码生成器。格式标志 `REGISTER=0x100` 表示描述符 `working_set` 保存私有入口偏移；原 `entry_offset` 仍为 C 入口。

## 2. 独占宿主耗时采样

每 16 个执行片段采一个，使用已验证的 256 Hz 硬件时钟，而非 SDK Tick。嵌套阶段切换先结算上一阶段，离开后恢复，避免将同一段 NAT 绘图时间同时计入 IRAM、核心和绘图。

日志新增 `host_exclusive_*_ticks`：核心剩余路径、IRAM 执行、NAT、绘图、文字、调用桥、文件读取、HLE 和语义模板。寄存器直连叶函数不再进入 C 计时桥，其时间属于 IRAM 执行段；另看 `native_register_calls`。

注意：这些是**被采样片段内**的时间，不是整场游戏时间。不能直接除以会话 RTC 或与 `bare_core_ticks` 相加。短函数可能落不到一个计时刻度；零 tick 不代表没有执行。读时钟的开销仍计入相邻阶段，日志暴露 `host_profile_clock_reads`。原绘图细分耗时也改为同一采样范围，尝试/接受次数仍是全量。

LIGHT 模式把旧 `s6502_performance_debug` 固定为零，因此新采样由前端仅在调试开启时提供的时钟指针控制，不复用旧标志。

## 3. 启动语义索引缓存

游戏旁生成同名 `.GAC`，例如 `GAME.GAM` 对应 `GAME.GAC`。只缓存已选模板的代码偏移与类别；不缓存宿主指针或直接重用原生地址。

- 检查分析器源码构建 ID、游戏长度、代码长度、代码内容哈希、缓存长度及载荷校验。
- 再验证每个模板、优先级及可达性，然后按当前内存重建索引和调用链接。
- 损坏、截断、旧版本、游戏内容变化、无法读取时重建；无法写入也不阻止游戏启动。
- 复用 CFG 队列存取，不新分配常驻缓存缓冲区。
- 候选超过临时队列的游戏也可缓存最终选择结果；不能只处理“小候选集”。

`load_analysis_cache_status`：0 未使用、1 重建但未保存、2 命中、3 重建并保存。首次启动仍需分析；主要缩短重复启动，并未宣称消除首次加载全部耗时。CFG/HLE 仍重新验证。

## 4. NAT 指纹去重

格式 5 把函数使用的指纹改成索引，唯一指纹单独保存；格式 4 仍可读取。

- 函数的第一个索引仍是精确可调用入口，其余只用于校验，不能跳到这些范围内部。
- 全部索引先做界限检查；字典上限 512，清单上限仍为 64 KiB。
- 清单从 58576 字节降到 24688 字节，减少 33888 字节，约 57.9%。
- 去重的是元数据，不改变函数语义或放宽 ROM 版本验证。

## 5. 解释核普通内存路径

STA/STX/STY 写 `$20..$FF` 直接按 RAM 基址寻址，省去通用页查找、屏幕脏范围检查和取指指针保存/恢复。低地址硬件寄存器、bank 和其他页仍走原路径；保持客机标志、周期及下一条取指行为。

## 验证与边界

- 主机：实际模板收集器的缓存命中等价、版本/内容变化、损坏、截断、关闭缓存。
- 主机：实际 NAT 新旧格式加载器、分配/释放、活动函数保护、无效索引拒绝。
- 主机：独占计时嵌套及 32 位时钟回绕；11000 组图形、1248 组文字 CPU/RAM/周期等价测试。
- S1C33 模拟器：IRAM 等价探针，包括直接 RAM 写入、标志位、页边界，以及寄存器叶函数对照 C 实现。
- 完整程序：另记录游戏启动、二次缓存命中、显示与退出检查结果。动画中途停机的 framebuffer 比较不能当作稳定画面通过。

交付必须同时替换 EXE 和 `gam4980/GAM4980.NAT`；保留现有 `8.BIN`、`E.BIN` 和游戏。安装包不得包含 GAM。

- 最终 EXE 668697 字节，NAT 174314 字节，142 个函数，其中 7 个带共享寄存器入口。
- S1C33 探针 15/15 通过；寄存器子测试为 7×64=448 个输入组合，与实际按入口专门化的 NAT C 实现比较，并检查寄存器入口命中计数。
- 《魔塔》进入文字页和地图：两次稳定画面校验均为 76800 像素、0 差异；长按退出返回桌面。NAT 图形和文字均实际命中。

- 《伏魔记》片头、标题、剧情已做启动检查；同一版本二次加载缓存状态由 3 变为 2。
- 动画途中曾有 framebuffer 快照差异（812 像素），没有记为通过；稳定《魔塔》画面已另行验证。没有声称所有动画提交时刻或所有游戏流程都已等价验证。
- 真机性能提升百分比尚无数据，不从调用次数、清单缩小比例或模拟器速度外推。
