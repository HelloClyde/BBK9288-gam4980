# IRAM 解释核取指指针保留实验

## 改动

- 普通零页/绝对地址存储以及内存读改写指令，在地址转换前保存操作数之后的宿主取指指针，完成后恢复，避免重新查找代码映射。
- CMP/CPX/CPY 的公共比较尾部只使用临时寄存器，不再破坏取指指针和 opcode 表指针。
- 合并重复的读改写地址检查，IRAM 从 5756 字节缩小为 5224 字节（减少 532 字节）。
- 上下文末尾增加 4 字节 transient saved_fetch，已有字段偏移不变。
- 保留普通完成尾部的页面边界检查、特殊地址慢路径、LCD dirty 处理及周期预算。没有取消客机语义检查。

## 验证

- `python -m unittest discover -s tests -p "test_*.py"`：128 项通过。
- S1C33 模拟器执行 `9288-FETCH-EQ.exe`：12/12 项通过。新增四个连续 LDA/STA/ASL/ROL/CMP 用例，输入 00/7F/80/FF，检查 PC、周期、执行条数、累加器、flags 和 RAM。原有用例包含跨页、十进制回退和特殊写入。
- 新 NAND 镜像中核验 EXE SHA256 后启动，文件选择、游戏启动画面、《伏魔记》开场剧情显示正常。本轮没有进行完整游玩或退出路径回归。
- 证据位于 `build/emulator-fetch-eq/` 和 `build/emulator-fetch-keep/`。

## 性能边界

剧情单次 QEMU 单指令 trace：IRAM 内执行 82278 条 S1C33 指令，完成 1216 条客机指令，约 1:67.66。EXT 单独计数；不把外部 HLE 的等价工作计入客机分母。

此前不同片段加权为约 1:67.30，因此这次抽样不能支持“整体显著提速”的结论。并非同一执行路径的严格 A/B，也不能用模拟器指令数量代替真机耗时。需要同场景真机日志判断实际收益。
