# 完整 framebuffer 提交对照版

用户在共享 ABI 6 版观察到持久白线：文字、位图都有，直到其他画面覆盖才消失；同时认可该版速度。真机日志基线为 268 秒、8493 客机帧，31.690 客机 fps，52.81% 标准速度。

本轮只调整呈现策略，不改变 IRAM/NAT/HLE 执行引擎：

- NAT graphics services 的 framebuffer/LUT 设为零，保留客机显存写入、bank/特殊地址语义、dirty 和计时服务。NAT 不再局部修改物理屏幕。
- 每次实际提交强制完整展开 159×96 为 318×192，位于 320×240 屏幕的 (1,24)，并清理白边。
- 完整提交不读取 dirty-row 或“已同步”标记来跳过行，与离线播放器 `c6502_native_present()` 的完整重写策略一致。
- 保留已有提交触发条件（客机画面改变或显示恢复），不是在每条指令、每个字形、每次空闲轮询都刷屏；不是 VSync/硬件翻页，也没有新增后台帧缓冲。
- 保留通用增量展开函数作测试/后备用途，但本版两个实际呈现入口均选择 full 模式。

新日志：`framebuffer_direct_version=2`、`framebuffer_full_submit=1`、`native_graphics_direct_mirror=0`。NAT 直写字节数应为零；完整刷新计数应跟随有效画面提交，而不再仅代表 SDK 恢复。

检查：1612 例独立像素模型测试通过，覆盖 carry、padding、边缘、保护区和无 dirty 的完整修复；入口策略检查确保不向 NAT 发布物理 framebuffer。

最终包模拟器检查：《魔塔》地图显示正常，76800 像素与客机 LCD 一致；NAT 直写字节和镜像写入计数均为零（文字行计数仍增长），退出返回桌面。NAT SHA256 与 ABI6-SHARED 版相同；EXE SHA256 为 `964b448c844ef7efd395ecc6eda521d91b55b85cf4a9a0b4925f2cd275cd8e46`。

此改动绕开了“物理画面有效性由客机数据/影子标记推断”的风险，但尚不能宣称已证明白线最初由哪个写入产生。最终白线效果与性能由真机对照确认。
