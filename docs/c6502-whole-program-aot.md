# C6502 编译器感知的整程序翻译

## 目标与边界

旧 A 系列开发包不再只用于给固件函数命名，而是作为 C6502 编译器规范使用。
加载 `.gam` 时，核心恢复代码范围、控制流、跨 bank 调用和编译器惯用语义，再把
它们绑定到 KF2 中预编译的 S1C33 超级指令。运行时不会生成机器码，因此不需要
可执行堆、指令缓存刷新，也不会把某个游戏固化进 EXE。

实现所用的离线资料是：

- `4980.cfg`：段、代码窗口和 bank 布局。
- `test.map`：固件、运行库和图形/输入 ABI。
- `RT.LST`：C6502 伪寄存器、算术、比较、参数和间接调用运行库。
- `psnake.lst`：带 `.c_start/.c_end`、`.bf_call` 和 C 注释的真实代码生成样本。

这些文件只是生成器输入，不属于 9288 运行时 SDK。9288 程序仍只使用
`app_env_9288` SDK 构建。

## 离线规格生成

[`tools/generate_c6502_spec.py`](../tools/generate_c6502_spec.py) 解析开发包并生成
[`src/s6502_c6502_spec_generated.h`](../src/s6502_c6502_spec_generated.h)。生成结果
包含：

- linker region、固件符号和 C6502 运行库 ABI；
- 可重定位的“字节 + 掩码”编译器模板；
- 每个模板的语义类型、长度和可静态分类的内存区域。

当前模板库识别 13 类高频语义：跨 bank 直接调用、两个 16 位立即数加载、两个
栈指针 16 位加减、字符/整数参数传递、两个零页 16 位加载、OPER1/OPER2 的
16 位加减，以及 `(zp),Y` 的 16 位加载/存储。原有七类控制流超级指令继续作为
冷代码回退层。

重新生成：

```bash
python tools/generate_c6502_spec.py \
  --kit /path/to/BBK旧A系列C语言开发包 \
  --output src/s6502_c6502_spec_generated.h
```

生成器测试会检查段布局、ABI 地址、模板掩码和确定性输出：

```bash
PYTHONPATH=. python tests/test_generate_c6502_spec.py
```

## 加载时 CFG 与语义 IR

加载器从 GAM 头的代码长度和入口 PC 出发，按 NMOS 6502 指令长度恢复可达 CFG：

1. 追踪顺序边、条件分支、`JMP`、`JSR` 和 `RTS/RTI/BRK` 边界。
2. 识别 `.bf_call` 后解析调用表，把目标 bank 和虚拟/物理 PC 加入工作队列。
3. 优先登记可达语义模板，再用保守扫描补齐不可静态到达的间接调用目标。
4. 固定表最多保存 4096 个入口；64 KiB 位图和固定队列不申请堆内存。

翻译记录不再复制最多 38 字节的客机代码，只保存物理 PC、语义、长度、链接目标
和内存分类，操作数字节直接从已加载的只读 GAM 存储读取。以《伏魔记》为例，
加载 294,912 字节代码得到 3,279 个入口，其中 3,157 个是 C6502 语义入口，
693 个由入口 CFG 直接证明可达。

语义超级指令一次完成整个 16 位表达式或 ABI 操作。它们使用活跃标志掩码，只计算
出口仍可观察的 N/Z/C/V；相邻模板在同一次 `s6502_exec` 内继续分派，因此 A/X/Y、
伪寄存器和中间标志不必在每条客机指令后重复写回。这相当于针对已知 C6502 ABI
的短语级 SSA、常量折叠、死标志删除和寄存器保持，而不是运行时调用一组逐指令
C 函数。

未识别指令、未知间接边、跨页模板、十进制算术和被修改的 Flash 始终回退到原
computed-goto 解释器。

## 跨 bank 直接链接

`.bf_call` 的调用表在加载时解析为目标 bank、虚拟 PC 和物理 PC。运行时先验证
当前三个表字节仍与链接结果一致，再验证当前 E.BIN 中以下真实桥接代码签名：

- `$D2F6-$D312`：`__banked_function_call` 前半段；
- `$F4A5-$F4F3`：取得当前 bank；
- `$F52A-$F5BC`：切换 bank 5–8；
- `$D572-$D585`：间接调用；
- `$E8F8/$E8FB`：两个跳板。

满足条件时直接完成 bank 5–8 映射，构造与原固件逐字节一致的客机栈残留和寄存器
状态，并让目标函数的 `RTS` 回到真实 `$D313` 后缀恢复旧 bank。它不是把被调函数
原子 HLE 掉：目标仍由 AOT/解释器执行，也仍在真实控制流边界返回调度器。

周期数包含当前 bank 路径、目标 bank 路径、两个 `(zp),Y` 跨页代价以及全部
桥接指令。周期预算不足、十进制模式、映射不连续、表被修改或固件签名变化时，
本次调用自动执行原桥接代码。

《伏魔记》600 帧中直链成功 295 次；5000 帧剧情轨迹成功 2,780 次。
《魔塔之怀旧终曲》和《三国霸业 6980》600 帧分别成功 421、1,768 次。

## 静态访存与 bank 状态

- 已知零页伪寄存器直接访问 RAM 后备数组，不经过通用 `mem_read/mem_write`。
- 固定代码操作数直接读取已加载 GAM 基址。
- 直接链接一次写入最终 bank 5–8 映射，目标块随即使用新的物理 PC；返回后由真实
  固件后缀恢复映射。
- I/O、page-0 映射寄存器、page-3 固件页和动态未知地址保留慢路径。

特别要注意 `$03D5/$03D6` 位于 page-3 固件映射，不能从普通 RAM 后备数组取值。
整程序直链开发中发现并修正了这一点；否则固件 bank 基址会被误读成零。

## 冷代码超级指令

CFG 未证明可达但静态字节匹配的代码仍可登记为超级指令，执行时以 24 位物理 PC
查表。它覆盖 16 位加载/存储、加减、指针间接访问、参数传递、比较/分支惯用形状
和固定目标 bank 调用。影子表不修改 GAM 原始字节，游戏读取自身代码时看到的仍是
原文件内容。

## 图片、字体与 LCD

固件图片/字体 HLE 的连续只读跨度使用 32 项映射感知缓存。缓存保存地址、长度、
首末页映射和源指针，不把资源展开成八套移位副本；bank 变化后验证失败便重新解析。
流式 ROM 600 帧回归中记录到 5,939 次命中、2,141 次未命中，状态与整片 ROM
加载模式一致。

客机 LCD RAM 始终逐字节保持真实内容，但每次写入只标记变化行。提交阶段用 nibble
查表一次展开四个客机像素并进行水平 2×，只重算 dirty 行；9288 仍通过真机兼容的
整帧 `SysBltFrame` 提交，不能把该 SDK API伪装成不存在的局部 blit。

## 事件截止周期执行

前端继续只使用兼容真机的 GUI `MSG_TIMER`。核心收到消息后，根据 ST1–ST4、STCT、
MT 和当前 400 周期相位计算最近的客机 Timer/IRQ 截止点，让 AOT/解释器连续执行到
该边界，再精确更新计时器和处理中断。它替代固定 `$800` 周期反复退出，但不会让
整函数跨过真实客机事件。

《伏魔记》600 帧的 `s6502_exec` 大块调用数为 1,701，执行 39,841,041 个客机
周期；截止周期调度开关不再依赖不可靠的 9288 墙钟 Tick。

## 内存与真机构建

9288 构建定义 `GAM4980_TARGET_9288`，把 AOT 表、CFG 位图/队列、ROM 缓存、资源
缓存和性能数组放到 loader 保留的 `.scratch`，避免启动代码逐字节清零大块
`.bss`。当前 `-O2` 轻量性能构建为：

| 项目 | 大小 |
|---|---:|
| KF2 | 822,497 字节 |
| `.text` | 379,636 字节 |
| `.rodata` | 33,779 字节 |
| `.bss` | 10,744 字节 |
| `.scratch` | 397,600 字节 |

这些都是 KF2 静态映像/loader 保留区，不从约 1.5 MiB 的动态 `malloc` 上限中再申请
一份，也没有 JIT 代码缓存。

## 等价回归

同一核心分别关闭/开启全部 13 类语义模板，以及关闭/开启跨 bank 直链，比较 CPU、
RAM、Flash、bank、Timer、LCD 和调度状态哈希：

| 游戏 | 轨迹 | 结果 |
|---|---:|---|
| 伏魔记 | 600 帧 | 语义 AOT与直链均逐状态一致 |
| 伏魔记 | 5000 帧剧情按键轨迹 | 直链逐状态一致 |
| 魔塔之怀旧终曲 | 600 帧 | 语义 AOT与直链均逐状态一致 |
| 三国霸业 6980 | 600 帧 | 语义 AOT与直链均逐状态一致 |

这证明的是行为等价，不代表主机计时能预测 9288 真机收益。性能回归仍应使用真机
最新 `PERF.LOG`；模拟器/主机负责确定性和画面回归。

## 仍可扩展的部分

当前是编译器感知整程序翻译的第一套可用实现，不声称已经恢复任意 C6502 程序的
完整高级 AST。后续可继续用原编译器在兼容环境中生成模板语料，扩充结构体字段、
32 位算术、`switch` 和更长循环；只有新模板通过随机逐状态回归后才加入默认集合。
