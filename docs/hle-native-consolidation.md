# HLE 功能级计算与去重（2026-09-10，fusion version 3）

这是 `hle-semantic-dedup.md` 后的继续实现，不是重新交付上一版两个优化。

## 实现清单

| 路径 | 本轮变化 | 共享/保留的边界 |
|---|---|---|
| 计数循环 | 除法折叠中间迭代，末轮也改为整值比较、加法和最终状态提交 | 内存别名、未知映射走兼容路径 |
| 记录扫描、反向扫描 | 16 位地址计算、比较、步长加减替换逐条 ADC/SBC 和寄存器搬运 | 分段入口与完整入口共用比较实现 |
| 回调扫描 | 计数、查表、空指针判断改为直接运算 | 在真实回调边界返回，不假设未知函数没有副作用 |
| 表查找、对象流程 | 直接计算结果，集中提交下一次调用需要的参数与栈 | 保持有别名可能的读写顺序 |
| 字形行地址 | `$6646` 的列归一化用除法/移位公式，移除普通 RAM 上的重复减八循环 | EXE ASCII/Chinese、NAT 和 flat 文字共用 `firmware_native_text_cursor.h` |
| 16 位乘法 | EXE 的逐轮移位加法改为宿主乘法；最终 CV 直接计算 | EXE/NAT 共用 `firmware_native_multiply_math.h` |
| 32 位运行库 | 已验证直接 RAM 上使用整值加减、逻辑、取反 | `firmware_native_long_math.h`；重叠、跨页、I/O 保留有序访问 |
| 运行库参数/间接调用 | 合并临时量返回适配，使用整值地址计算和最终栈镜像 | 返回值之外只生成调用者会观察到的最终状态 |
| bank 切换 | 描述符地址和连续窗口用直接算术计算 | 保留真实 bank 寄存器的写入顺序 |
| 位图移位行 | 行周期公式替换按列求和 | 普通像素路径已有 packed/native 合成；NAT 从同一算法源生成 |
| 字节传输 | 完整和分段传输合用一个实现 | 源是自动递增端口，不能错误替换成 memcpy |

最终 flags 不是逐指令 flags 模拟：算法只计算调用者分支所需的最后结果。
原始函数写入过的栈位置可能被调用者读取，因此适配层保留最终栈镜像；不执行一串模拟 PUSH/JSR/RTS。

## 为什么仍存在兼容代码

本轮清理的正常匹配路径已采用功能级计算，但不能宣称整个项目不再包含任何客机状态模拟：

- I/O 自动递增、bank 控制、源目标重叠时，访问顺序本身属于功能，必须保留。
- 游戏可能从内部入口续执行；不能把它误当作公共函数的全新调用。
- 未通过 RAM/别名检查的状态使用原有兼容实现或解释器，不强行套用公式。
- 整数除法、软件浮点的位运算循环是宿主算法，不等于逐条 6502 解释；不能仅因为看见循环就删掉。

EXE 和 NAT 是两个独立装载单元，共享算法源不等于删除其中一个装载单元所需的机器码。
NAT 的多入口地址绑定也不是多份独立算法。公共绘图的整帧提交及白线修复保持不变。

## 回归

- `tests/test_hle_native_consolidation.py`：字节传输、乘除运行库、C 运行库、bank 和六类游戏链的原始 ROM 对照。
- `tests/test_hle_fusion_three.py`：共享比较 100 万组、计数折叠、位图与直接 RAM 路径。
- `tests/test_firmware_native_text.py`：1,248 组真实 ROM 对照与 PIC 检查。
- `tests/test_firmware_native_graphics.py`：11,000 组 CPU/RAM/周期/LCD 对照与 PIC 检查。
- `tests/test_native_atomic_contracts.py`：116 入口 × 512 组状态/访存测试。
- `tests/test_function_native_specialization.py`：129 入口、264,192 组特化对照。

日志标识为 `hle_fusion_version=3`。这些是正确性测试，不能换算为真机加速百分比。
