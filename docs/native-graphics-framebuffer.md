# 动态 NAT 绘图与文字（2026-09-08）

后续优化见 [架构审查优化批次](review-optimization-2026-09-08.md)：当前服务版本已为2，逐字节镜像改为行片段批量提交，并用显示快照消除帧末重复输出。下文保留初始ABI5版本的实现和验证记录，不代表最新逐项行为。

这版将已经验证的图形/字形计算移入 `GAM4980.NAT`，并在 NAT 内直接展开、写入9288物理 framebuffer。不是 NAT 调回 EXE 的绘图 HLE。

## 范围与加载

新包为 format 4、ABI 5，共142个函数：原129个运行库函数，加11个图形入口、2个字形入口。

| 类型 | 精确客机入口 |
| --- | --- |
| 图片头、恢复、移位区、位图区、行尾链 | `$682D/$690F/$6988/$5C5D/$6B1A/$6BA4` |
| 地址计算、横线中段、局部图片行、像素尾部 | `$876B/$8039/$5351/$5801/$859E` |
| ASCII、汉字行合成及行指针更新 | `$650F/$608A` |

这些是经过验证的计算入口；除 `SysPicture` 头部外，不代表全部公共 API 的序言已经重写。`SysAscii/SysChinese` 的入口参数和字模定位仍可经原固件到达上述字形计算入口。其他未迁移入口、游戏绘图 HLE 和通用访存也没有被宣称全部原生化。

加载 GAM 的已有 CFG 扫描记录公共 API 调用，补充其计算依赖，再按函数分配和预载。未发现的间接调用首次使用时加载；未用到的函数不因属于同一图形类别而全部驻留。包继续验证物理 bank、精确入口和 ROM 指纹。HLE 关闭时跳过图形/字形预载和执行。

`--firmware-native-rom` 构建默认开启 `GAM4980_NATIVE_GRAPHICS_ONLY`，取消这13处旧 EXE HLE 跳转；链接器移除重复算法。缺 NAT、ROM 不匹配或预算不足时仍可解释执行，不跳进不兼容的原生代码。因此安装时必须同时更新 EXE 和 NAT，不能用旧129函数包来评价本版性能。

## 写屏契约

NAT 实际合成字节 → 正确更新客机 RAM/别名/dirty → NAT 内联查表，2×展开到 `0x003c0000`。不调用9288 GUI 绘图函数，不经 `g_screen_frame` 整屏复制。

仍保留客机显存，因为游戏会读回、遮罩、反色和覆盖它。输出为159×96、居中2×、坐标 `(1,24)`；第160个隐藏位保留在客机RAM但不显示。folded 显存的 `$400/$1000/$ff3` 差别、邻字节边界均有测试。

framebuffer 指针只在裸机模式成功进入后开放，恢复桌面前清零。文件系统服务仍走原来的安全所有权转换；回到游戏后保留整屏修复。帧末脏行提交也保留，用于覆盖解释器/其他 HLE 的写入和 SDK 恢复；它可能再次展开已经被 NAT 镜像的行，当前不是完全消除重复提交的方案。

ABI 5 在104字节旧执行上下文之后追加服务指针，旧字段偏移不动；服务只提供客机访存、映射、输入检查点及屏幕所有权，没有 EXE 绘图算法回调。图形代码不占用 IRAM。

## 性能日志

- `native_graphics_attempts/accepted/zero_returns`、`native_text_*`：计算入口尝试、接受、预算或条件回退次数，不是公共 API 调用数。
- `native_graphics_host_ticks`、`native_text_host_ticks`：调试开启时对实际 NAT 调用计时，使用256 Hz硬件时钟；包括内部访存和即时写屏，但不包括进入函数前的缺页加载。最大单次耗时另记 `max_host_ticks`。
- 这些耗时已经包含在 `bare_core_ticks`，不能再加一次；`bare_render_ticks/bare_present_ticks` 仍只表示帧末处理。
- 每tick约3.906ms，短调用可能测得0；计时读取也有开销，不能将0解释为无耗时，更不能拿模拟器计时推导真机性能。
- `native_graphics_lcd_bytes` 是 NAT 实际写入宿主 LCD 的字节数；和帧末 `framebuffer_direct_bytes` 分开记录。

## 验证

可复现测试：`test_native_graphics_io.py`（14,903案例）、`test_firmware_native_graphics.py`（11,000完整CPU/RAM/周期/LCD案例及11入口无重定位检查）、`test_firmware_native_text.py`（1,248真实E.BIN解释器对照、双入口无重定位）、`test_native_function_loader.py`（ABI4兼容、ABI5、HLE开关、按函数驻留和失败清理）。

字形对照发现旧 `$6646` 行指针ADC/SBC未正确更新V；新NAT按真实固件修复。所有字模仍取自原游戏/固件资源，不用9288字体替换A系列字体。

隔离模拟器验证：伏魔记片头、主菜单、剧情、地图及对话正常，NAT图形/文字接受调用分别41,839/16,629，退出恢复桌面，`bare_restore_ok=1`。地图/静止对话各76,800像素与实时客机显存一致。逐字打印中途与上一帧快照比较会产生差异，故不把中途截图当成完整帧等价检查。

最终构建另测魔塔：进入第一层，生命1000、攻防10、金钱/经验0显示正常；图形/文字接受调用3,638/474，累计NAT直写186,728字节。预载28个函数、实用加载44个、驻留原生代码67,132字节，未发生淘汰；整屏76,800像素与实时客机显存一致。ROM反向索引与单次NAT索引构建检查通过。

最终 EXE 660,321字节，SHA256 `81c8bf37b810f4ff348051474b21f78536348beb5dd9c4decb39838f28d371e6`；NAT 198,064字节，SHA256 `a8a6295222408b9bed2619f7da5f80918ab7b6facf956066c755fa11f88f08d1`。manifest58,576字节，IRAM仍5,392字节。EXE比DIRECT-FRAMEBUFFER基线少14,688字节，但实际总RAM还取决于按需加载的函数，不能只凭EXE减小判断内存收益。

这不是全游戏流程回归。真机性能应由同一路线新旧日志比较，不预先宣称提速比例。
