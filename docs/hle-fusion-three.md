# 三项热路径优化

基于 HLE-PATH-PROFILE，针对真机计数循环、D362 和位图路径。

## 计数循环连续批处理

比较并递增后，在同一已验证的匹配入口内继续执行，省去重新进入 HLE 搜索、AOT 哈希和执行分派。
每轮仍从实时 RAM 计算成本并保留完整寄存器、flags、栈副作用和客机周期。
仅在计数地址处于 $0400..$1FFF 且预算足够时串接，不将特殊地址、潜在 bank 写入跨过去。
这不是直接跳到最终计数值的数学折叠，也没有取消客机事件边界。

## D362 原生比较

两个四字节操作数均处于有 READ_DIRECT 标记、已驻留且单页连续的映射时，直接按页指针读取，省去八次通用读回调。
跨页、未驻留和特殊读映射继续原路径；保持字节顺序、非零差值字节数、进借位、溢出、栈和返回 ABI。
NAT 原有原子契约不变；不改变 IRAM ABI，不额外占用 IRAM。

## 位图四像素融合

沿用已有整行路径，目标各页确认为恒等映射普通 RAM（排除 $2000 控制页），且掩码表已驻留连续时，将一个源字节的四个像素合并，共用一次 X 更新和目标边界检查。覆盖游戏实际使用的 $34xx 目标区，不仅测试用的 $04xx。
不跨中途目标写入：只用于初始 X<=4；其他情况保留逐像素路径。
掩码表不复制，仍读实时内容；资源读取可能替换缓存，因此读取后重新解析表指针。
支持物理连续的跨页八字节表（伏魔记 OR 表在 $52F9）。像素内容、可写 RAM、行末状态和周期不变。
保持已修复白线的整帧提交路径，未引入物理屏幕逐 tile 提交。

## 日志

`hle_fusion_version=1`，`hle_counter_chain_hits` 和 `hle_bitmap_packed_groups` 为轻量版采样范围内的事件计数（`hle_fusion_counts_sampled=1`），不是全会话次数。
`hle_function_profile_version=2` 将误导性的 accepted 改名为 `hle_sample_completed_segments`，它不是调用成功率的分子。

## 验证

`tests/test_hle_fusion_three.py`：计数 4096 组与未串接 HLE 对比完整 CPU/RAM/周期；D362/D340 12000 组与回调路径对比；位图原有 ROM 对照 50960 组（另有内部段完成事件），并断言新路径确实命中。
入口专门化 129 入口、264192 例回归通过。性能增益需同路径真机日志确认。

最终目标构建 IRAM 审计通过（5332 字节）。独立模拟器启动游戏，计数串接采样 3756 次、位图打包组 1126 次，NAT 正常加载；76800 像素与已提交快照零差异，退出键返回桌面。不是全游戏流程或所有系统菜单分支穷举。
