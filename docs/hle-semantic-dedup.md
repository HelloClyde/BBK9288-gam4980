# HLE 算术化与共享实现（2026-09-10）

> 本文保留 fusion version 2 的历史结果。后续完整清理见
> [HLE 功能级计算与去重](hle-native-consolidation.md)，测试包日志标识为 version 3。

## 本次实际修改

- 游戏计数循环：同高字节、递增、稳定普通 RAM 的匹配循环，用除法计算本次周期预算能完成的迭代数，一次加法跳过中间迭代。保留最后一次边界适配，产生与原路径一致的寄存器、零页临时量、栈残留和周期。不是改成更快的逐轮分派。
- 比较：新增 `firmware_native_compare_math.h`，用宿主 16/32 位减法计算结果，并一次生成必要的最终 flags 和非零结果字节数。EXE 的 D340/D362、游戏比较周期计算和 NAT 比较共用该算法，不再分别实现逐字节借位/flags 模拟。
- 访存顺序、返回地址和调用约定仍由各入口适配层处理；它们不是多份比较算法。NAT 不因共用源码而依赖 EXE 中的固定代码地址。

## 安全边界

计数批处理只跳过没有对外副作用的中间轮次；不同高字节、零增量、指针与编译器临时量别名、非普通 RAM 等继续使用兼容路径。末轮仍按原语义处理溢出，预算不足时不跨过客机事件边界。比较保留最终 flags，是因为调用者直接用 flags 分支，不是为了维护无用的中间状态。

没有宣称所有 HLE 已改为功能级重写：内部位图/移位续执行入口、记录/对象/回调处理链，以及部分运行库入口仍有状态适配或旧算法。不能仅因它们同属一个公共 API 就删除内部入口。已验证的公共图片/文字原子绘图保持不变，本次不改变屏幕提交方式。

## 验证与观测

- 共享比较：1,000,000 组独立逐字节参考对照。
- 固件运行库：140,000 组 CPU/RAM/周期等价用例。
- 计数循环：4,096 组真实 GAM 匹配入口等价用例；56,835 轮实际被折叠。
- 位图：50,960 组既有等价用例。
- NAT 原子契约：116 入口 × 512 组状态/访存测试通过。
- 日志 `hle_fusion_version=2`，新增 `hle_counter_folded_rounds`。该计数在轻量日志中仍是采样计数，不是整个游戏会话总量；旧 `hle_counter_chain_hits` 包含折叠轮次，不能将两者相加。

以上是正确性验证，不是整机性能提升百分比。真实收益必须用相同游戏路径的真机日志判断。
