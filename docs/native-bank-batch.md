# 原生 bank 批量映射与 D2F6 入口（2026-09-09）

## 依据

真机日志 `4d016325-3f7c-46fd-8133-d994d34b8f2c`：F52A 和 D313 共 1621 个采样独占 ticks，占 4904 个已报告阶段采样 ticks 的 33.05%，占 NAT 函数榜的 76.90%。D2F6 采样尝试 2331 次、接受 0 次；旧日志没有拒绝原因，不能直接断言这些全部由地址限制引起。

## 批量映射

服务结构扩至版本 5，追加 `bank_map4`、`bank_descriptor_safe`、诊断指针。NAT 仍为包格式 5 / 共享 ABI 6，EXE 和 NAT 必须配套。

F52A 原生实现保留参数计算、暂存区初始化、栈和 flags，使用单次宿主服务更新窗口 5..8。原路径每个窗口分别写低字节、高字节，调用映射更新两次；新路径每个窗口只调用一次 `mem_bs`，仍同步页属性、IRAM 分派、NAT bank 路由和 ROM 缓存锁定。

中途不执行客机指令/IRQ，因此这些窗口的临时半更新映射无需对客机可见。没有取消实际 ROM 缺页服务和所有权处理。服务保持原 callback-depth 保护，避免加载路径淘汰执行中的原生代码。

前置检查确保零页仍是 bank I/O、$2000 仍对应普通 RAM 暂存区。不满足时返回零且不修改状态，NAT 回到旧回调路径。最终保留 12 位 bank 掩码、选择器 8、$2000 高字节、完整寄存器/栈与周期记账；没有把 bank 函数改成合成 6 周期。

## D2F6

旧入口只接受 `$0400..$0FFD` 的三字节函数描述符。新入口允许实际读映射已确认的稳定 RAM、ROM、普通 Flash 描述符：

- 不跨地址末端；不在本次会重映射的 `$5000..$8FFF` 内，也不能跨入该范围。
- 不允许物理低 RAM 控制/栈别名或 `$2000..$2002` 暂存区别名。
- 特殊 I/O、Flash 命令模式及其他未知读映射保留拒绝。
- 未截获的旧服务版本保留旧范围限制，不越界读取新增字段。

仍使用原有实时读回调读取描述符，不缓存一个可能在切换后失效的宿主指针。

新增 `native_bank_batch_*`（尝试、接受、更新窗口数）和 `native_d2f6_*`（尝试、十进制拒绝、描述符拒绝、预算拒绝、接受、首末拒绝地址、扩展范围接受与首地址）。这些是次数/地址，不是耗时。

## 验证

`tests/test_bank_batch.py` 分别构建旧兼容路径与新服务路径，对照真实 6502 ROM 调用/返回状态。新路径 10000 例包括固定低 RAM、扩展 RAM 和 ROM 描述符；20000 次批量服务实际接受，7500 次扩展入口接受，10000 次短预算拒绝。另 256 个分布于整个 16 位范围的 bank 输入核对选择器、掩码/进位、全部最终页指针和读写函数。

无效描述符边界检查、129 入口专门化 264192 例、公开绘图 5 项、内部图形 11000 例回归通过。目标包编译对所有入口检查无外部重定位，IRAM 仍 5332 字节。

性能需要新真机同路径日志确认，不能把减少一半映射调用直接换算为整机加速。
