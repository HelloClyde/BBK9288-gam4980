# 架构审查后的优化批次

## 本批已落地

1. IRAM wrapper 用独立的 bit 30 标识已知 SLOW 返回。外层直接执行慢指令，不重进 IRAM；bit 31 强制退出在零周期时也生效。汇编返回 ABI 未改。
2. RAM/ROM bank 映射检查物理 bank、实际 backing pointer 和页面读写类型，未变时不重写 16 页映射、不重算 page kind。ROM cache 查询和特性分派刷新仍保留；Flash 命令模式不走此捷径。新游戏清空有效标记。
3. NAT 图形/文字使用实时读页表直接读取；普通 RAM 页直接写，保留 LCD dirty、PB=0、AutoPowerOffCount=0xff。零页 I/O、page-3、Flash、ROM 继续走原始回调。不是把所有地址当 RAM。
4. NAT 连续 LCD 写合并成行片段，通过 `fw_gfx_lcd_span` 批量 2× 展开。行变更或函数结束时提交，保持客机 RAM 逐次写入顺序及重叠资源语义。图形提交每四行增加输入检查点；文字保留原每四字形行检查点。
5. 增加 1920 字节宿主显示快照和 12 字节有效位。NAT 同步记录实际提交片段；帧末相同行不再提交。跨片段边界像素不能确认一致时使整行失效。SDK 恢复的强制刷新无条件执行，不用缓存跳过。
6. 已驻留固件函数最多连续调用 32 次，共用一次 context；遇预算、停止状态、非固件页、未命中即返回。原生函数内部仍用 C ABI，这不是完整寄存器 ABI。`native_shared_chain_links/max_chain` 记录实际串联。

图形服务版本为 **2**，执行上下文仍是 NAT ABI 5。EXE 和 NAT 必须配套更新，旧服务版本不匹配时函数拒绝执行。行提交子程序在每个 NAT 函数包内部共享，使用可搬移的同段相对调用；打包器按真实入口符号确定 entry_offset，不能假设段首总是函数入口。

## 构建与内存

构建只使用 `D:/Downloads/app_env_9288`，没有修改 SDK 或模拟器。

- EXE：662,973 字节。
- NAT：207,290 字节；142 函数，原生代码147,750字节，manifest58,576字节。
- IRAM：5,392字节，不变。

## 回归与性能边界

- 11,000 图形 CPU/RAM/周期/像素等价案例；含 RAM 别名、重叠、预算不足、物理屏幕快照有效性检查。
- 1,248 字形真实 E.BIN 解释执行对照案例。
- 13个绘图/文字入口 S1C33 无重定位检查；内部相对调用可随函数载入地址移动。
- 1,611 屏幕展开案例；包括边距、隐藏第160位、脏行边界、无脏行零写入。
- 实际外层 SLOW 代码片段及原生链单元测试：零周期强退、不重复重进、预算、停止、32调用上限、零返回。
- ROM cache 32/64/128行配置对照通过；bank 索引各构建配置对照通过。Windows ASAN 运行库缺失的配置跳过，不算通过。

模拟器用于功能和像素等价验证，不用其耗时推算真机提速。新版本尚无真机日志，不能承诺倍数提升。

最终文件在独立模拟器实例验证：伏魔记片头、主菜单、剧情文字和长按退出；魔塔标题、剧情、地图HUD及长按退出均正常。最终NAT的魔塔地图HUD、剧情静态画面分别与实时客机RAM对照76,800像素，差异0。伏魔记剧情也取得差异0的检查点，但滚动中的另一次异步截停有638像素差异，可能停在未完成提交中；不把该次检查列为通过，也不据此宣称全程逐时刻等价。

## 尚未完成的架构项目

- 真正私有寄存器 ABI（NAT 函数直接承接 A/X/Y/SP/PC/P，不通过 context）。
- 互不重叠的宿主耗时归因与低开销基准模式。
- 加载期语义分析持久缓存、manifest 指纹去重。
- 根据新的真机数据决定进一步的解释核指令融合。

这些不能用“已串联原生函数”替代宣称完成；本批保持现有客机事件预算，不采用放宽周期语义换取表面帧率。
